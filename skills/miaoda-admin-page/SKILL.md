# 后台与仪表盘生成

先找一个可验证的工作回路。例如，采购员对同一批次的报价核对含税单价和交期，选择供应商后回到待办；运营人员先选归因口径，再从趋势下钻到渠道或订单。第一屏应能开始这段工作。

用两条需要不同处理的记录试排首屏。“少收 2 箱”和“缺测温时间”都可属于待复核，决定先打开哪条的是差异、对象和时间。把这些字段放在队列中，原始单据和处理动作留给选中项。逐个检查首页已有的摘要、彩色标记和说明，它们应帮助定位记录、比较证据或完成操作。

| 工作重心 | 桌面布局 | 信息和动作 |
| --- | --- | --- |
| 台账与工单 | 标题与主要动作同一行，筛选贴着结果列表，详情由行内入口打开。 | 标识、对象、状态和下一步优先。金额与单位对齐，排序和翻页保留条件，批量动作显示选中范围。 |
| 审核与比价 | 左侧队列配主详情，或上方固定比较对象、下方按相同维度排成列。 | 统一税费、单位和时间口径，标出差异。通过、退回显示影响和处理记录，操作完成后更新队列与计数。 |
| 阶段流转与排程 | 阶段看板以工单为卡片；按天排班用日期轴与人员行，并提供列表查看。 | 显示负责人、冲突和待处理事项。草稿、已生效和历史版本各有明确标记。为拖动提供按钮或选择器替代。 |
| 趋势分析 | 先给时间与口径，摘要后用一张主图回答趋势问题，再放构成或可核对的明细。 | 图表与明细共享筛选；金额、比例、单位写明。单值优先排成文本，比较用条形、趋势用折线。点击异常数据能定位相应记录。 |
| 目录与运维 | 用树或窄导航定位对象，中央显示记录，选中后才展开属性、历史或操作。 | 监控状态同时有文字，告警按紧迫度排序。日志与图表共用时间范围，长 ID 可复制。 |

**选视觉。** 审核台可用冷灰和细边界，让差异突出；采购比价可用暖纸底和紧凑数字；夜间监控用深背景和少量高亮系列。状态色跨页保持同义。多模块才需常驻导航，单工作流可使用顶栏加局部切换。在固定主题工程里优先复用 Table、Form、Drawer、Tabs 与语义令牌，用页面层实现空间和图表层级。

**密度与窄屏。** 桌面行高可从 40–48px 起调，给名称较长的对象更多列宽。窄屏先留下对象、状态、金额或截止时间；次要字段到详情，密集比较表可在独立区域横向滚动。打开筛选或详情后能关闭并回到原记录。

**交付检查。** 用有长名称、同名对象和不同状态的数据走一遍筛选 → 查看 → 操作 → 返回。核对统计与列表、筛选无结果和首次空台账、加载失败与重试、提交中与实际成功。模拟数据需明确来源；真实保存、权限与并发结果以服务端响应为准。

可在 [风格目录](../miaoda-case-styles/SKILL.md) 选择冷色运营、暖纸经营、看板排程、亮色或夜间分析。

[来料异常复核](references/receipt-review.html) 是可离线打开的收货账。桌面同时查看清单与单据，手机点批次进入详情，复核后返回清单。示例使用内存数据，生成业务应用时将复核写入项目已有的服务端。
