# 企业后台版式配方

以下是根据七个公开项目提炼的妙搭设计建议。每节开头记录来源能直接观察到的做法，后面给出可调整的排版和交互。外观与数字是原创示例。可打开[离线样张](gallery.html)逐项对照。

<a id="receipt"></a>
## 采购收货单

芋道把采购订单、入库与退货串成可追溯的单据。ERPNext 的收货行记录来源订单、合格量、拒收量及各自入库去向。[芋道采购单据](https://doc.iocoder.cn/erp/purchase/) · [芋道前端](https://github.com/yudaocode/yudao-ui-admin-vue3/blob/c67f1345e8139f194ecb40a5d5ba11e9a939d020/src/views/erp/purchase/in/PurchaseInForm.vue) · [ERPNext 收货行与截图](https://docs.frappe.io/erpnext/purchase-receipt) · [ERPNext 收货明细定义](https://github.com/frappe/erpnext/blob/d4a11406378bb9e31ee88d0b5e21abf46c839823/erpnext/stock/doctype/purchase_receipt_item/purchase_receipt_item.json)

- **单据结构。** 首行给单名、单号、草稿或已过账状态。供应商、来源采购单、收货仓排成紧凑单头。把主要宽度留给物料与数量。单身按物料组织，同一行相邻放本次到货、合格、拒收，合计注明单位。多单位分别小计。
- **纸面排版。** 单头和总计用较重的横线，明细用细线。标识符和数量用等宽数字。可编辑数量格有清晰边界，普通只读数值直接排字。异常色只落在异常数量和原因上。窄屏以一项物料为一组，数量标签跟着输入框。
- **试排。** PO-0641 的密封圈订购 120 件，本次到货 100 件，其中 96 件合格、4 件破损转待退仓。首屏能区分余下 20 件和已到的 4 件。回改拒收数量时重验本次分配，成功过账后再显示回执。

<a id="contracts"></a>
## 合同台账

腾讯 TDesign Starter 的合同列表把合同状态与收付款方向直接放在各行。下面的待结算金额和到期日是财务跟进场景的扩展。[TDesign 合同列表](https://github.com/Tencent/tdesign-vue-next-starter/blob/5b8bb52a16472629d53d991c402489508bc10ba1/src/pages/list/base/index.vue)

- **账簿排版。** 合同名称与对方单位占最宽的一列。按任务选择签约额、待收或待付余额、到期日，表头标明币种。金额右对齐、保留相同小数位，方向写“应收”或“应付”。用留白和行线引导横读，仅给逾期或即将到期的项强调色。
- **筛选与动作。** 对账时先选方向和结算范围，再按到期日排序。分期合同展开当期应结、已结与下次到期日。有收付款登记能力时行操作写明“登记收款”或“登记付款”。窄屏摘要保留合同、方向、余额和到期日。
- **试排。** 同一客户有一笔 36,000 元应收和一笔 8,400 元应付。去掉颜色后仍能分辨方向。查看一份已结清的合同并返回，筛选保留，已结余额显示为 0.00；金额未知时显示缺数说明。

<a id="review"></a>
## 连续审单

SAP Fiori 的 Flexible Column Layout 允许 List Report 和 Object Page 并列显示。把这种并列关系用于异常复核，可以在同一位置连续读取多张单的证据。[SAP Fiori 列表与对象页](https://github.com/SAP-samples/fiori-elements-feature-showcase/blob/ecbb43c7a152a57e454758675d100129375c5855/README.md#flexible-column-layout)

- **双栏排版。** 桌面队列约占三分之一，每行首行放业务对象，下行放差异及时间。详情首行重复选中对象的单号；原始值、报送值、差额在同一基线上。选择态通过行底色与边缘同时体现。差异原因用短句，处理动作放在当前详情内。
- **连续处理。** 切换队列时证据、原因和可用动作一起换。提交中的记录保留在位；成功后按需求移出或移到已处理，失败时保留输入。手机先显示队列，进入单据再看横向对照，返回原行与筛选。
- **试排。** 承运商账单比运单多列 180 元，另一条记录仅缺签收凭据。前一条突出金额差及两张来源单，后一条突出缺少哪一份凭据。两条都写“待复核”仍应一眼能选出要处理的那条。

<a id="directory"></a>
## 组织人员目录

若依用户管理把可搜索的组织树与用户表格并排，点击部门会改变人员查询的范围。[若依用户管理](https://github.com/yangzongzhuan/RuoYi-Vue3/blob/465b3ed4c2ab270f041eabd466145f7e8449fd41/src/views/system/user/index.vue)

- **树与名册。** 部门面板宽度随层级和长名称调整，给选中节点一条连续底色。名册以真实部门名作范围标题，姓名和工号紧邻，岗位与在职状态各占一列。分栏间一条竖线即可。长路径可在范围标题中换行。
- **查找与返回。** “查部门”只定位树节点，“查姓名或工号”在当前范围筛人。显示是否含子部门。手机用部门选择器收起树，在名册上方保留部门路径。详情返回当前节点。
- **试排。** 华东仓与苏州仓各有一名陈禾。按用户选定的部门层级和工号区分两人；搜不到时显示当前部门及清除筛选入口。

<a id="query"></a>
## 运营查询

Arco Design Pro 的查询页将编号、类型、时间与状态组织成条件区，表格可调密度与列。适合要反复查找不同结果集的工作。[Arco 查询页](https://github.com/arco-design/arco-design-pro-vue/blob/27020819af653243b7b1a3e8e2481d6b3d798749/arco-design-pro-vite/src/views/list/search-table/index.vue)

- **查询排版。** 将最常用的 2–4 个条件贴着结果上方排成一行，低频条件再展开。结果表标题附近给已应用条件与条数。说明性长文本让位给能区分对象的编号、来源和时间。相邻编号等宽排，区分日期与时刻。
- **结果范围。** 明确点击“查询”生效还是即时生效。若手动查询，编辑中的条件与当前结果分开。批量操作写出作用范围，跨页全选需明确。手机以筛选面板修改条件，收起后仍能看到已应用条件。
- **试排。** 查“西区仓、失败、今天”的同步记录。能定位失败记录的时间和批次；把范围改成没有结果的一天，可直接移除日期限制。

<a id="entry"></a>
## 分步录入

Ant Design Pro 把分步表单、高级表单列为独立页面模式。本配方用于录入顺序有业务依赖、提交前需要复核的场景。[Ant Design Pro 页面目录](https://github.com/ant-design/ant-design-pro/blob/42f2cb1d303380909ea04c73b5e60679d09c321a/README.zh-CN.md)

- **表单排版。** 给步骤起业务名称，例如“收款对象、银行账户、确认资料”。单栏输入限制在便于阅读的宽度，账户名用完整一行。确认页改用同序的标签和值，保留对应“修改”入口。当前步骤用实心指示与文字强调，完成与待填状态可用文字辨认。
- **编辑过程。** 按字段类型设置宽度、校验与错误位置。前一项决定后一项可选值时，回改后复核依赖字段。短录入直接在同页完成。窄屏优先显示当前步骤、进度和下一步操作。
- **试排。** 在确认页发现收款账户尾号错误，返回账户步骤修改后再确认。摘要反映新尾号并保留已填资料。保存草稿与正式提交的反馈分别对应真实操作。
